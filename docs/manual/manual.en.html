1What Caption Studio does

Caption Studio writes training captions for LoRA datasets. You set one recipe for the whole dataset, select images or video clips, and the application saves a caption file next to every original.

  • Image models: plain .txt descriptions or tags (FLUX.2, Klein, Z-Image, Krea 2, Qwen-Image, SDXL and any trainer that reads a .txt file per image) and structured .json for BRIA FIBO.
  • Video models: a separate caption file for WAN 2.2 (text-to-video and image-to-video), LTX-2.5 and MiniMax H3, each in the shape its prompts use. Photos and clips can be in the same dataset.
  • Four kinds of LoRA: a character or person, an object or product, a visual style, or a general dataset. Each kind names its subject in its own way and offers its own choice of details.
  • Three ways to run the vision model: a cloud API; a local server, above all Marvin, our local Qwen harness (or Ollama, LM Studio, llama.cpp and others); or a model that Caption Studio downloads and runs itself.

Quick start

  1. Install Caption Studio and start it (chapter 2).
  2. In the setup, connect a cloud API or Marvin (or another local server), or download the model (chapter 3).
  3. Click ＋ Open folder and choose the folder with your dataset.
  4. In the recipe, choose What are you training?, the Caption output and the name the LoRA should learn.
  5. Click Create captions, then review the results in the right panel.
No graphics card required Caption Studio runs on any Windows 10 or 11 computer. With a cloud API the images are analyzed by the provider, so you do not need a powerful graphics card. A card is needed only if you want to run the model on your own computer.
RECOMMENDED

Local captioning with Marvin

With an NVIDIA card (16 GB or more), run the model on your own computer with Marvin, our local AI harness for Qwen3.8 27B (github.com/petrsajner/marvin). Start Marvin and Caption Studio finds it with one click: free, private and the same model for both applications. See 3.1.

3.1 Marvin: the recommended local model

RECOMMENDED

Marvin is a local AI harness for Qwen3.8 27B on NVIDIA graphics cards, made by the author of Caption Studio. Besides serving the model to Caption Studio, it is a complete local assistant: chat, a coding agent, image analysis, research and more. Model, chats and files stay on your computer.

  • The same Qwen3.8 27B vision model as Caption Studio's own download, with image support built in.
  • Profiles measured on real cards; the graphics memory figures in this manual come from Marvin.
  • A large context (up to 192k tokens), so even 30-frame clips fit easily.
  • One model for both applications: no second download in Caption Studio.

Download: github.com/petrsajner/marvin, the Full installer (recommended for a new PC; it includes everything and downloads the model during setup).

  1. Install Marvin and start it. Marvin starts its model server by itself, at http://127.0.0.1:8080/v1.
  2. In Caption Studio's setup, click ◎ Local and then Find local servers.
  3. Click the server http://127.0.0.1:8080/v1. Caption Studio lists it as the llama.cpp address, because Marvin runs a llama.cpp server. The address and the model (for example q5) fill in by themselves; no key is needed.
  4. Click Save and continue →.
Keep Marvin running while you caption Caption Studio never starts or stops Marvin. Closing Marvin stops the model and frees the graphics card, for example before you train a LoRA.

3.2 Cloud API

  1. Click ☁ Cloud API.
  2. Choose the Provider: OpenRouter, OpenAI, Google Gemini, or Other compatible API. The API address fills in by itself; for another provider, enter its base address (HTTPS, usually ending in /v1).
  3. Paste your API key. You get it in the provider's account, for example in Google AI Studio (Gemini), on the OpenAI platform or in OpenRouter under Keys.
  4. Click Load available models and choose an Image-capable model, for example gemini-3.8-flash. You can also type the exact model ID.
  5. Click Save and continue →.

The key is stored encrypted for your Windows account and only for this API address; every provider keeps its own key. When a key is saved, leave the field empty to keep it. To delete it, tick Remove this provider's saved key and save.

Choose a model that accepts images The model list can include text-only models. If the model rejects images, choose another one. For video clips the model receives up to 30 frames in one request.

3.3 Other local servers

Any other application that serves a vision model through an OpenAI-compatible API works the same way. The model stays in its application; Caption Studio connects to it but never starts or stops it.

  1. Start the API server in your application and load a vision model there.
  2. In the setup, click ◎ Local and Find local servers; click a server that answers.
  3. Or choose Connection type → Existing local server and enter the Local API address yourself.
  4. If the server needs a key (for example Unsloth), enter the Local API key.
  5. Click Load models, choose the Image-capable model and click Save and continue →.
Application Usual address
Marvin http://127.0.0.1:8080/v1
Ollama http://127.0.0.1:11434/v1
LM Studio http://127.0.0.1:1234/v1
llama.cpp (llama-server) http://127.0.0.1:8080/v1

What the local model must handle Only local addresses (localhost, 127.0.0.1) are accepted in Local mode. A model in the list does not have to support images, so choose a vision model. For clips it must accept up to 30 images in one request; give it a large context (at least 64k tokens). Marvin meets all of this out of the box.

3.4 Your own downloaded model

Caption Studio can also download and run the model itself: Qwen3.8 27B with a vision projector, on a bundled llama.cpp runtime. Use this when you want Caption Studio on its own; with Marvin you can skip this section.

  1. Click ◎ Local and choose Connection type → Caption Studio managed runtime.
  2. Choose the Model profile that fits your graphics card (table below).
  3. Choose the Compute backend: NVIDIA · CUDA 13.3 for NVIDIA cards, AMD / Intel / NVIDIA · Vulkan for other cards, or CPU · slow without a suitable card.
  4. Click Download runtime and model. The progress bar shows the download; Pause interrupts it and the next attempt resumes where it stopped. Every file is checked (SHA-256) before use.
  5. When the badge shows Ready, click Save and continue →. The model starts automatically with your first batch; Start model starts it right away.

Release GPU stops the model and frees the graphics memory, for example before you train. Closing Caption Studio stops it too.

3.5 Supported graphics cards

All four profiles are the same Qwen3.8 27B model with different precision. Choose by graphics memory (VRAM):

Profile Download Graphics card Measured VRAM Free disk Notes
Q2 9.8 GB 16 GB 13.0 GiB ≈ 13 GB Smallest; images are analyzed on the graphics card
IQ3 12 GB 16 GB 13.6 GiB ≈ 15 GB Images are analyzed on the processor: slower, about 3 minutes per 30-frame clip
Q4 16.5 GB 24 GB 18.9 GiB ≈ 20 GB Default. About 18 s per 30-frame clip
Q5 19.8 GB 32 GB – ≈ 23 GB Highest precision

VRAM was measured by Marvin on an RTX 5090 with a 64k context and does not include other programs. The free disk space includes the vision projector (0.93 GB) and the runtime (about 2 GB). Marvin runs the same model on the same measured profiles, so the table applies to it as well.

  • NVIDIA with 16 GB or more (for example RTX 4080, 4090, 5080, 5090): Marvin, or the CUDA backend of your own model. Keep the NVIDIA driver up to date.
  • AMD Radeon or Intel Arc with 16 GB or more: Vulkan backend. It is offered but not tested on every card.
  • Less than 16 GB or no graphics card: use a cloud API, or a local server with a smaller vision model. The CPU backend works but is very slow.

3.6 The rest of the setup

Interface language switches the application between English and Czech immediately. It does not change the language of your captions; that is set in the recipe.

Setting Choices What it does
Longest side for analysis 768, 1 024, 1 536, 2 048 px The model receives a copy resized to this size. Larger sees more detail but is slower and, in the cloud, costs more.
Request timeout (s) 30–900, default 240 How long to wait for one answer. Raise it for a slow model or long clips.
Clip frames for analysis Every 0.25, 0.5 or 1 s How often a frame is taken from a clip. At most 30 frames of about one megapixel; longer clips get 30 frames spread evenly.

The originals never change: the model receives a resized copy without EXIF metadata. Click Save and continue → to store the setup.

5Step by step: from images to captions

  1. Prepare the folder. Put the images (and clips) of one dataset into one folder, with unique file names. See chapter 6.
  2. Load it. Click ＋ Open folder, find the folder in the preview and click Use this folder. All images appear as cards; captions that already exist are marked Existing.
  3. Say what you train. In What are you training? choose Character / person, Object / product, Visual style or General dataset, and fill in the name (and, for a character or an object, its type).
  4. Choose the output. In Caption output choose the file for the model you will train, for example Normal · .txt for FLUX.2 or All video models for WAN, LTX and H3.
  5. Choose the details. Tick what should stay changeable with prompts; untick what the LoRA should learn. Apply defaults for this LoRA type gives a good start.
  6. Check the instructions (optional). Preview model instructions ↗ shows exactly what the model will be asked.
  7. Try a few images first. Untick Select all, tick two or three cards and click Create captions. Read the results; adjust the recipe if needed.
  8. Caption the rest. Tick Select all and click Create captions. With Skip existing captions on, finished images are not processed again.
  9. Review. Filter To review and Errors, click each card, fix the caption and save it with Ctrl+S. Use ↻ Regenerate for a new attempt.
  10. Train. The caption files are next to the images; point your trainer (for example LORA Train) at the folder. See chapter 13.

6Preparing the dataset

Caption Studio describes images; it does not crop, resize or convert them. Prepare the dataset before captioning. The full guide to a good LoRA dataset (how many images, variety, resolution per model) is in the LORA Train manual; here are the essentials.

Images

  • Square images work best, for example 1024 × 1024 px. Most trainers handle other aspect ratios with buckets, but square crops keep the subject large and consistent.
  • Sharp, well-lit images without watermarks, frames or collages. Remove near-duplicates.
  • Variety in what should stay free: different backgrounds, lighting, poses and clothing for a character; different subjects for a style.
  • Supported formats: JPG, JPEG, PNG, WEBP, BMP, TIF, TIFF. Multi-frame images (animated) are not supported.
  • Unique names: photo.jpg and photo.png would share photo.txt. Caption Studio reports such conflicts before writing; rename one of the files.

Video clips

Supported formats: MP4, MOV, WEBM, MKV, M4V, AVI. Cut the clips to the length the model trains on before captioning; Caption Studio reads them and never changes them.

Model Trains on
WAN 2.2 (A14B) 16 fps, up to 81 frames, about 5 s
WAN 2.2 I2V (A14B) 16 fps, up to 81 frames, about 5 s; the first frame is the start image
LTX-2.5 24–25 fps, up to 121 frames, about 5 s
MiniMax H3 24 fps, clips of 5–15 s

The name the LoRA learns (trigger)

  • Use one invented, readable word that the base model does not know: Velmira for a character, Zorbo for an object, Zorvak for a style.
  • Avoid short tokens such as sks; trainers also find them inside other words. Avoid names of real people and brands.
  • Use the same name in Caption Studio and in your trainer.

Existing captions

If the folder already contains caption files, they are loaded and shown as Existing. With Skip existing captions on, only images without the selected caption file are processed.

7The dataset recipe

The recipe in the left panel applies to every selected image. All changes are saved automatically (Settings saved appears at the bottom of the panel).

7.1 What are you training?

This choice decides how every caption names what the LoRA learns, which fields you fill in and which details you can choose.

Type Fields A caption starts
Character / person Character name, Character type Velmira, a woman, sits…; later “the woman” or “she”
Object / product Object name, Object type Zorbo, a backpack, hangs…; later “the backpack” or “it”
Visual style Style name Zorvak style, a woman sits…
General dataset Trigger word (optional) ohwx, a woman sits…

Character and object: the name and the type are written once, where the subject is first mentioned. The type (a woman, a man, a backpack) also tells the model which pronouns to use. Write it in the caption language; video captions are always English.

Visual style: the caption describes only the content (people generically), never the medium or technique, so the style belongs to the name. A name that already ends in “style” is used as it is.

General: a plain description; the trigger word, if any, is placed at the start.

7.2 Caption output

Choose the file for the model you will train. Every output has its own file next to the image:

Output File For Content
Normal name.txt photos A description or tags, in English or Czech
BRIA JSON (FIBO) name.json photos BRIA's structured fields: subject, objects, scene, lighting, composition…
WAN 2.2 name.wan.txt photos, clips Plain sentences: subject and action, details, setting, lighting, shot
WAN 2.2 I2V name.wan-i2v.txt clips Only the motion and the camera movement; the start image shows the rest
LTX-2.5 name.ltx.txt photos, clips One present-tense paragraph that opens with the shot
MiniMax H3 name.h3.txt photos, clips The three official fields, starting with [Shot 1]; sound is N/A
All video models all four above photos, clips Creates every video file that applies in one batch

The files coexist: creating one never changes another, so one folder can serve several trainers. Normal and BRIA describe photos only; clips show Video models only there.

7.3 Format, language and length

  • Format: Description (sentences) or Tags (comma-separated). Applies to Normal captions.
  • Caption language: English or Czech, for Normal and for the values in BRIA JSON (its keys stay English). Video captions are always English.
  • Target length: 20–300 words, default 100, including the name. It is a soft target: captions up to 120 % are kept; a longer one is sent back to the model for a shorter version. Text is never cut off mechanically. BRIA JSON has no word target.

7.4 Choosing what to include

This is the most important part of the recipe. The rule: what the caption describes stays changeable with prompts; what it leaves out, the LoRA learns.

  • ON (ticked) = described in every caption = free to change in future prompts.
  • OFF (unticked) = left out = fixed in the LoRA.

Example: for a character you leave out the face and hair color (the LoRA learns them) but describe the hairstyle, clothing and background, so you can later prompt “Velmira with a ponytail, in a red coat, on a beach”.

Every type has its own details and remembers its own choices: switching the type shows that type's details, and switching back restores what you chose. Apply defaults for this LoRA type leaves out the details in bold below. The line above the list shows how many details are included.

Type Details (bold = OFF by default)
Character / person Identity / subject appearance, Hair color, Hairstyle, Clothing, Accessories, Pose and action, Facial expression, Environment and background, Lighting, Composition and camera, Visual style
General dataset The same details as a character; all are ON by default
Object / product Object appearance, Logo and text on the object, Variant and state, Placement and orientation, Use and interaction, Environment and background, Lighting, Composition and camera, Medium
Visual style What is depicted, Pose and action, Environment and background, Light situation, Composition and camera, Medium and technique, Color palette and grading
Clips (any type) Motion over time, Camera movement: shown when a video output is selected

Tips per type

  • Character: hair color and hairstyle are separate. A character's hair color usually belongs to the LoRA; its hairstyle (loose, ponytail, bangs) stays free. If the character always wears the same outfit and it should be part of the LoRA, turn Clothing OFF.
  • Object: people who hold or use the object are described generically. If the product comes in several colorways that should stay promptable, say so in Additional instructions; Variant and state then names the colorway.
  • Visual style: Light situation describes the time of day and light sources; how light is rendered belongs to the style. Colors of single things are still described even with the palette OFF.

7.5 Additional options

Option What it does
Include readable image text Readable text in the image (signs, labels) is written into the caption.
Additional instructions Your own instructions for the whole dataset, for example “The backpack comes in three colorways; name the colorway.” or “Do not judge aesthetic quality.”
Preview model instructions ↗ Shows the complete instructions the model receives for the current recipe.
Skip existing captions Images that already have the selected output's file are not processed again.
Save captions automatically ON: every finished caption is written next to its image. OFF: results stay as drafts until you save them.

The name is not in the instructions: the model writes a placeholder, and Caption Studio inserts the name and type into the finished caption, so the name appears exactly once.

In ai-toolkit and musubi-tuner, point the caption extension at the model's file, for example caption_ext: "wan.txt" or caption_extension = ".wan.txt".

How the video captions differ

  • WAN 2.2 starts with the name, then the subject and action, details, setting, lighting and the shot.
  • WAN 2.2 I2V describes only what moves and how the camera moves (at most 100 words), because the start image already shows everything else. It is created for clips only.
  • LTX-2.5 opens with the shot, then the name, in one paragraph in the present tense.
  • MiniMax H3 uses its three fields; the description starts with [Shot 1], a photo is a static shot, and sound and music are N/A.

9Working with images and clips

Loading

  • ＋ Open folder opens a folder preview with thumbnails, a folder tree, a path bar and ← Back, Forward →, ↑ Up one folder, ⌂ Home and ↻ Refresh. Click Use this folder to load it.
  • ＋ Select images opens the Windows file dialog for single files.
  • Path… lets you paste a folder path directly.
  • Include subfolders also loads the images in subfolders.
  • Add to the open dataset adds the new images to the current list; without it, the new folder replaces the list (no files are deleted).

One dataset can hold up to 20 000 files. The dataset and unsaved drafts are kept when you close the application.

Counters, selection and filters

The counters show how many images are waiting, captioned, have errors or are to review. The tick box on a card selects it for the batch; clicking the card opens it in the review panel. Select all selects everything that the current filter shows. Search by file name, filter by All, Without captions, With captions, Errors or To review. Large datasets are shown 60 cards per page.

Card states

State Meaning
Waiting No caption for the selected output yet
Queued, Analyzing… In the running batch
Saved The caption was created and saved
Existing The caption file was already there when the dataset was loaded
Skipped Not processed because Skip existing captions is on
Draft Created but not saved yet (automatic saving is off)
To review The model's answer needs your check, for example an incomplete ending or JSON that could not be repaired
Error, Conflict / error Processing or saving failed, for example the file was changed outside the application; the review panel says why

A clip shows its length and size on the card. With a video output selected, each card shows badges for the model files that exist (WAN, I2V, LTX, H3).

10Creating captions

  1. Select the images and clips (tick boxes or Select all).
  2. Click the button in the bottom right. Its label follows the output: Create captions (5), Create BRIA JSON, Create WAN 2.2 captions, Create captions for all video models. The number is the count of selected items.
  3. Images are processed one at a time. The bottom bar shows the current file and progress; the cards change state as they finish.
  • Stop batch stops the batch. Saved captions stay; an answer received so far is kept as a draft.
  • If the connection to the model fails, the batch pauses. Fix the cause and click Continue: finished images are not repeated. Discard batch ends it instead. After a restart, an interrupted batch can be continued the same way.
  • With your own model, the first batch starts the model; loading it into graphics memory takes a moment.

What happens automatically

  • Length: a caption over 120 % of the target is sent back for a shorter version (up to two attempts). If it is still long, the shortest complete version is kept with a notice.
  • Incomplete endings are completed by the model; if that fails, the draft is kept To review.
  • BRIA JSON is checked and repaired when needed; an unrepaired answer stays a draft to review.
  • The name is inserted where the subject is first mentioned. If the model named the subject more than once, later mentions use its type.
  • Existing captions are never lost: a replaced file is backed up first.

11Reviewing and editing captions

Click a card to open it in the right panel.

  • Tabs above the editor show every caption file of the image (.txt, .json, .wan.txt…); a tick means the file exists. The word count is shown on the right.
  • Edit the text and click Save caption or press Ctrl+S. The previous version is kept in the .caption-backups folder next to the images.
  • ↻ Regenerate creates the caption of the open tab again, for this image only.
  • Model responses keeps every answer the model returned (original and shortened). Choose one and click Use in editor.
  • Notices below the editor explain what was done, for example “The name was added at the start.”, or warn: “The trigger appears more than once in this caption.”
  • BRIA JSON: Format JSON indents the JSON. It is checked when saved.
  • MiniMax H3 files are checked for their three fields when saved.

If you switch to another image with unsaved edits, Caption Studio asks whether to discard them.

Clips

For a clip the review panel shows:

  • a player,
  • size, length, frame rate, frame count and audio,
  • what the selected video model trains on (for example “WAN 2.2 (A14B) trains at 16 fps with up to 81 frames, about 5 s.”),
  • the frames sent to the model, each with its time,
  • a tab for every video caption file.

The frames show exactly what the model saw. If a quick movement is missed, set Clip frames for analysis to every 0.25 s (chapter 3.6).

12Files, data and privacy

Caption files

  • Captions are saved next to the images, in UTF-8: image.jpg → image.txt.
  • Every output has its own file; saving one never changes the others.
  • A replaced caption is first backed up byte for byte into .caption-backups.
  • If a caption file changes outside Caption Studio (in another editor), it is not overwritten. Load the dataset again to continue.
  • Original images and clips are never changed.

The data folder

Everything the application stores is in the data folder next to CaptionStudio.exe (installer: %LOCALAPPDATA%\Programs\Caption Studio\data).

Item Contents
settings.json Recipe, connections and interface language (without keys)
keys.json API keys, encrypted for your Windows account
session.json The open dataset, drafts and model answers
runtime\models The downloaded model and vision projector
runtime\model.log Diagnostics of your own model
logs, app.log Application logs, without captions, images or keys

The data folder survives updates and uninstalling. Saved keys work only for your Windows account; on another computer, enter them again. If the program folder cannot be written to, the data is kept in %LOCALAPPDATA%\CaptionStudio and the application tells you.

Privacy

  • Local mode (Marvin, another local server or your own model): images never leave your computer. The bottom bar says Local mode · images stay on this computer.
  • Cloud mode: resized copies of the selected images (or clip frames) without EXIF metadata, and the recipe, are sent to the provider. The bottom bar names the host they go to.
  • Keys are encrypted with Windows (DPAPI) and kept separately for every address.
  • The application runs only on your computer (127.0.0.1) and is not reachable from the network.

13Training with LORA Train

LORA Train reads the caption files straight from the dataset folder; there is nothing to export. Each training profile reads its own file:

14Troubleshooting

Problem or message What to do
Windows protected your PC when installing Click More info → Run anyway.
The application opens in the web browser instead of its own window Microsoft Edge WebView2 is missing (for example the installer had no internet). Install “Microsoft Edge WebView2 Runtime” from Microsoft, or keep working in the browser. Closing the tab leaves the application running.
Caption Studio is already running. Switch to the open window; only one copy runs at a time.
Caption Studio could not start. The details are in app.log in the data folder.
The model did not start or stopped unexpectedly Update the graphics driver, close programs that use graphics memory, choose a smaller profile, or try the Vulkan backend. Details are in runtime\model.log.
Insufficient disk space, Download failed, Checksum mismatch Free up space or check the connection and click the download button again; it resumes.
No running server was found. Start Marvin (or the API server of your application) and click Find local servers again, or enter its address under Existing local server.
Connected, but the list is empty. Load a model in the server's own application first, then click Load models.
Invalid API key., Insufficient credit. Check the key and the credit in the provider's account, then click Continue.
The request rate limit was reached. Wait a moment and click Continue.
The model rejected the image request The model probably does not accept images. Choose a vision model.
The model connection timed out. Raise the Request timeout or lower the Longest side for analysis.
The caption was changed outside the app. Load the dataset again (Open folder).
Two files would share the caption file… Two images have the same name with different extensions. Rename one.
The existing caption is not UTF-8 text. Save that file as UTF-8 in a text editor, or remove it, and load the dataset again.
Many captions To review Open them, fix and save, or use Regenerate. With a small or slow model, raise the timeout or use a stronger model.
